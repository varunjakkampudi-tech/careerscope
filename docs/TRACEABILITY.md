# Requirement traceability matrix

One row per requirement feature, mapping it to its source document, the files
that implement it and the test files that cover it. `npm run traceability:check`
(`scripts/ci/check-traceability.mjs`, part of `npm run check`) fails if any path
named in the **Implementing files** or **Covering tests** columns does not exist,
if a row has no implementing file, or if a row names neither tests nor
`NOT COVERED`.

Scope and limits:

- The feature list is derived from [Product surface](PRODUCT-SURFACE.md) (routes,
  `PS-*`) and [API surface](API-SURFACE.md) (endpoint groups and platform
  behaviour, `API-*`). Neither document carries a numbered "Stage 1 to 11" list,
  so rows are keyed by surface rather than stage. Add the stage reference to a
  row's requirement text when the owner supplies the stage register.
- A test file is listed when it exercises the feature. It is not a claim of
  complete branch coverage. Browser checks (`scripts/tests/check-ui.ts`) run in
  the browser CI suite, not in `npm run test:unit`.
- A covering test file must be run by CI: its path has to appear in a `package.json`
  script that CI executes (`test:unit`, `test:integration`, `test:domain`, `test:ui`,
  `test:query-budget`, `gates:test`, including the npm scripts they call). A file that
  only runs on demand carries an explicit `(manual)` marker after its path, and the
  check fails if a `(manual)` file is in fact run by CI.
- `NOT COVERED` means no test file that exercises the feature was found. These
  rows are gaps, not waivers.
- Every file path is written in backticks, relative to the repository root.
