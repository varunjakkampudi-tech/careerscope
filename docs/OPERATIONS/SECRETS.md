# Operations — Secrets

No secret value appears in this repository, in this document, or in any log.
This file records **where** each secret lives and **how** to rotate it.

---

## Inventory

| Secret                                | Location                                                | Generated by          | Only copy?                      |
| ------------------------------------- | ------------------------------------------------------- | --------------------- | ------------------------------- |
| `POSTGRES_PASSWORD`                   | `/opt/careerscope/infra/v3/.env` on the host            | `deploy.sh`           | **Yes**                         |
| Resume encryption key                 | `careerscope_private` volume, `/private/encryption.key` | `bootstrap`           | **Yes**                         |
| TLS private keys and ACME account key | `careerscope_certificates` volume                       | Caddy / Let's Encrypt | Recoverable by re-issuance      |
| SSH deployment key                    | operator workstation, `~/.ssh/careerscope_deploy`       | operator              | Backed by hPanel console access |
| Session tokens                        | `sessions` table, stored hashed                         | API at login          | n/a                             |
| Password hashes                       | `users` table, Argon2id                                 | API at registration   | n/a                             |

`infra/v3/.env` is gitignored. `.env` and `.env.*` are gitignored repository-wide,
with `.env.example` the only exception.

---

## Rules

- **Never** commit a secret. `.gitignore` covers `.env`, `*.tgz`, `data/`,
  certificates and keys; do not add exceptions.
- **Never** log one. The API logger redacts `req.headers.cookie`,
  `req.headers.authorization`, `password` and `token`, and request logging is
  disabled in favour of a hand-written record containing only the route
  template, status, duration and a request id — never URLs, query strings or
  bodies.
- **Never** put one in documentation, an issue, a screenshot or a chat message.
- **Never** regenerate `POSTGRES_PASSWORD` against an existing database volume.
  The volume will reject it and the stack will not start.

## Rotation

### Database password

Requires coordinated change, because the volume holds the old credential:

```sql
ALTER ROLE careerscope WITH PASSWORD '<new>';
```

Then update `/opt/careerscope/infra/v3/.env` and restart via
`restart-stack.sh`. Do it in that order — changing the file first leaves the
stack unable to connect.

### Resume encryption key

There is no rotation procedure. Stored resumes are encrypted with the current
key; replacing it makes every existing object undecryptable. Rotation would
require a re-encryption pass that does not exist. Treat the key as permanent
for the lifetime of the volume.

### TLS

Caddy renews automatically. Certificates and the ACME account key persist on the
`careerscope_certificates` volume, which is why a restart does not re-request
them and burn issuance quota. Verified: the certificate serial is unchanged
across a proxy restart.

### SSH key

Add the new public key to `/root/.ssh/authorized_keys` **and confirm a fresh
session works** before removing the old one. `harden-ssh.sh` refuses to run
when no authorized key is present, but it cannot protect you from removing the
key you are currently using.

## Owner account

The owner account is created with `setup-owner` inside the API container.

- Public registration stays disabled (`REGISTRATION_ENABLED=false`).
- Never invent or choose a password on the owner's behalf; use the one they
  supply and never print it.
- There is **no forgot-password or reset flow** — no email sender exists. If
  the owner loses the password, recovery is `setup-owner` on the host.
  See [KNOWN-LIMITATIONS](../KNOWN-LIMITATIONS.md).
